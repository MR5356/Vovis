# 发布更新日志

每次发布前，在本目录创建与新版本对应的 `版本号.md`（不带 `v` 前缀），填写这次发布的具体更新内容，再推送对应版本标签。比如 `v1.2.3` 必须有 `release-notes/1.2.3.md`：

```markdown
- 修复 Windows 检查更新失败时误报“无新版本”的问题。
- 启动发现新版时展示更新日志，下载时显示进度。
```

CI 在开始构建前检查该文件；文件缺失、为空或只有标题、占位文本时拒绝发布。同一份内容写入 GitHub Release 和应用使用的 `latest.json`，用户可以在更新弹窗中阅读。

已发布的版本和安装包不可覆盖。即使只是修复打包问题，也需要使用新的版本号并填写日志，已安装的应用才能识别版本升级。未发布的草稿可以重试构建和上传。
